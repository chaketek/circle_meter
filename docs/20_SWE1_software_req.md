## 1. CAN 受信・デコード

| ID | 要求 | 上位 | 検証 |
|---|---|---|---|
| `SWR-01` | TWAI ドライバを **NORMAL モード**、500 kbps、アクセプタンスフィルタ `0x200`–`0x20F` で初期化すること。受信フレームには ACK を返す（`RSK-10`） | `SYS-01`,`SYS-07` | `IT-01`,`IT-04`,`IT-15` |
| `SWR-02` | TX/RX の GPIO 番号はビルドフラグ `CM_TWAI_TX_GPIO` / `CM_TWAI_RX_GPIO` で変更できること（既定 13 / 15 = PORT.A） | `DOC-12 §3.1` | `IT-01` |
| `SWR-03` | 受信フレームを 32 要素以上の FreeRTOS キューに積み、UI 側の遅延で取りこぼさないこと。キュー溢れはカウンタで記録すること | `SYS-06` | `IT-03` |
| `SWR-04` | フレーム ID を `(id - baseId)` のオフセットに変換し、オフセット 0–11 のみを処理すること。それ以外は無視カウンタを加算して破棄すること | `SYS-02` | `UT-01` |
| `SWR-05` | 11 bit 標準 ID と 29 bit 拡張 ID の両方を設定で受け付けること | `DOC-13 §1` | `UT-01` |
| `SWR-06` | DLC が 8 未満のフレームは破棄し、不正フレームカウンタを加算すること | 堅牢性 | `UT-10` |
| `SWR-1A` | 送信キュー長を **0** で初期化し、万一 `twai_transmit()` が呼ばれてもキューイングできないようにすること（`RSK-06` の第 2 層） | `SYS-07` | `IT-04` |
| `SWR-07` | λ1 を `0x207` の byte0-1（uint16 LE × 0.0001）からデコードすること | `SYS-03` | `UT-02` |
| `SWR-08` | EGT1 を `0x209` の byte0（uint8 × 5）からデコードすること | `SYS-04` | `UT-03` |
| `SWR-09` | RPM・水温・吸気温・MAP・油圧・バッテリ電圧・CEL/λ プロテクトフラグをデコードすること | `SYS-05` | `UT-04` |
| `SWR-10` | デコード処理は**ハードウェア API に依存しない純粋関数**として実装し、`native` 環境で単体テスト可能であること | `DEC-06` | `UT-*` 全般 |

## 2. 信号モデル・鮮度管理

| ID | 要求 | 上位 | 検証 |
|---|---|---|---|
| `SWR-20` | 全信号について `値 + 最終更新時刻 + 妥当性` の 3 つ組を保持すること | `SYS-40` | `UT-08` |
| `SWR-21` | 信号の状態を `FRESH`（500 ms 以内）/ `STALE`（500–2000 ms）/ `LOST`（2000 ms 超、または一度も受信なし）の 3 値で返すこと | `SYS-40`,`SYS-41` | `UT-08` |
| `SWR-22` | `LOST` の信号について、直前の値を返さないこと（API が明示的に「値なし」を返すこと） | `RSK-01` | `UT-08` |
| `SWR-23` | λ < 0.30 および EGT ≤ 0 を無効値として扱い、`LOST` 相当とすること | `SYS-42`,`RSK-09` | `UT-09` |
| `SWR-24` | 表示用の値に 1 次 IIR ローパス（時定数: λ = 80 ms, EGT = 200 ms）を適用すること。生値も診断用に保持すること | `SYS-12`,`DOC-13 §3.2` | `UT-11` |
| `SWR-25` | λ → AFR 変換は `AFR = λ × stoich` とし、`stoich` は設定値（既定 14.70、範囲 5.0–20.0）とすること | `SYS-14` | `UT-06` |
| `SWR-26` | 信号ストアへの書き込み（CAN タスク）と読み出し（UI タスク）はデータ競合なく行えること。読み出しは一貫したスナップショットを返すこと | `DEC-03` | `IT-03` |
| `SWR-27` | λ の警告色ゾーンを判定する関数を持ち、境界値ちょうどの入力に対して決定的な結果を返すこと | `SYS-11` | `UT-05` |
| `SWR-28` | EGT の警告レベル（`NORMAL` / `WARN` / `DANGER`）を判定すること。閾値は設定値（既定 850 / 920 °C） | `SYS-16` | `UT-07` |

## 3. 表示

| ID | 要求 | 上位 | 検証 |
|---|---|---|---|
| `SWR-40` | LVGL を 240×240 の円形ディスプレイに対して初期化し、M5GFX 経由でフラッシュすること | `DEC-01` | `IT-14` |
| `SWR-41` | 描画バッファは内部 SRAM から 240×120（RGB565）を 2 面確保し、`LV_DISPLAY_RENDER_MODE_PARTIAL` で動作すること | `DEC-05` | `IT-14` |
| `SWR-42` | λ リングバーは `lv_canvas` 上に自前で描画し、5 色ゾーンと現在値インジケータを 1 パスで描くこと | `DEC-02` | `QT-02` |
| `SWR-43` | λ ページのフレームレートを 30 fps 以上に保つこと。FPS は実測してカウンタに記録すること | `SYS-12` | `QT-03` |
| `SWR-44` | 数値表示は視認性のため専用フォント（数字のみ・太字・大サイズ）を用いること | `STK-01` | `QT-02` |
| `SWR-45` | 表示単位（AFR / λ）の切替はボタン短押しで即時反映し、設定を NVS に保存すること | `SYS-14`,`SYS-35` | `IT-06` |
| `SWR-46` | 警告発生時、該当数値の色変更に加え、画面外周に警告帯を描画すること | `SYS-16` | `QT-05` |
| `SWR-47` | バックライト輝度を LEDC PWM（G9）で 5 段階以上に制御すること | `SYS-20` | `IT-05` |
| `SWR-48` | オープニング画面はロゴ画像をフェードインし、最大 1.5 秒で次画面へ遷移すること。ロゴ画像は差し替え可能な形式で保持すること | `SYS-18`,`OPN-05` | `QT-06` |

## 4. ページ管理・入力

| ID | 要求 | 上位 | 検証 |
|---|---|---|---|
| `SWR-60` | ページを共通インタフェース（`create` / `update` / `destroy` / `onButton`）で抽象化し、新規ページの追加が既存ページの改変を伴わないこと | `SYS-60` | レビュー |
| `SWR-61` | 初期ページ構成は ① λ メイン ② λ + EGT デュアル ③ エンジン情報（RPM/水温/吸気温/MAP） ④ 電装（バッテリ電圧/油圧/油温） ⑤ 診断 とすること | `STK-06`,`SYS-62` | `IT-06` |
| `SWR-62` | エンコーダ回転 1 ディテントでページを 1 つ送る。末尾で先頭に循環すること | `SYS-30` | `IT-06` |
| `SWR-63` | エンコーダ回転の取りこぼしを防ぐため、回転検出は割り込み駆動またはハードウェアパルスカウンタで行うこと | `SYS-34` | `IT-06` |
| `SWR-64` | ボタン短押し（< 600 ms）／長押し（≥ 1500 ms）を区別すること。チャタリング除去は 20 ms とすること | `SYS-31`,`SYS-32` | `UT-12` |
| `SWR-65` | 設定メニューで変更可能な項目: 表示単位、λ レンジ、λ 色境界、EGT 警告/危険閾値、理論空燃比、輝度、CAN ベース ID、CAN ビットレート | `SYS-14`,`SYS-20` | `IT-05` |
| `SWR-66` | タッチ入力はページ内スクロール等の補助に限定し、ページ遷移・設定変更の唯一の経路にしないこと | `SYS-33` | `QT-07` |

## 5. 設定の永続化

| ID | 要求 | 上位 | 検証 |
|---|---|---|---|
| `SWR-80` | 設定を NVS の名前空間 `circlemeter` に保存すること。設定構造体にはバージョン番号とチェックサムを含めること | `SYS-35`,`STK-14` | `IT-05` |
| `SWR-81` | 保存済み設定のバージョンが不一致、またはチェックサム不正の場合、既定値で初期化して起動を継続すること（起動失敗させないこと） | 堅牢性 | `UT-13` |
| `SWR-82` | 設定変更は変更確定時に即座に保存すること（電源断で失わないため） | `DEC-07` | `IT-05` |

## 6. 異常処理・診断

| ID | 要求 | 上位 | 検証 |
|---|---|---|---|
| `SWR-90` | TWAI のバスオフを検出したら `twai_initiate_recovery()` を呼び、1 秒間隔でリトライすること。復旧回数をカウントすること | `SYS-43` | `IT-07` |
| `SWR-91` | タスクウォッチドッグを有効にし、UI タスク・CAN タスクを監視対象に登録すること（タイムアウト 3 秒） | `SYS-44` | `IT-08` |
| `SWR-92` | 診断ページに以下を表示すること: 受信フレーム/秒、破棄フレーム数、キュー溢れ数、TWAI エラーカウンタ (TEC/REC)、バスオフ復旧回数、スナップショット取得失敗回数、実測 FPS、空き内部ヒープ、稼働時間、ファームウェア版数 | `SYS-62` | `IT-13` |
| `SWR-93` | 起動後 5 秒以内に有効フレームが 0 件の場合、「WAITING FOR ECU」画面を表示すること | `SYS-45` | `IT-02` |
| `SWR-94` | パニック時（例外・アサート失敗）は自動再起動し、直前のリセット要因を診断ページに表示すること | 堅牢性 | `IT-08` |

## 7. 開発・テスト支援

| ID | 要求 | 上位 | 検証 |
|---|---|---|---|
| `SWR-100` | ビルドフラグ `CM_ENABLE_CAN_SIM` を有効にすると、実 CAN の代わりに内蔵シミュレータがフレームを生成すること（λ・EGT をスイープ） | `SYS-61` | `IT-12` |
| `SWR-101` | PC 側から CAN フレームを再生してベンチ試験を行えるよう、CSV 形式のフレームシーケンス仕様を定義すること | `QT-*` | `IT-12` |
| `SWR-102` | ファームウェア版数（git describe）をビルド時に埋め込み、診断ページとシリアルログに出力すること | `SUP.8` | `IT-13` |
