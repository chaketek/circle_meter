# CAN ベンチ試験記録 2026-10-05（LCD-2.1 / 実 CAN 版）

LCD-2.1 の 12PIN（D+ = GPIO20 を TX、D− = GPIO19 を RX）に M5Stack Unit Mini CAN を繋ぎ、PEAK PCAN-USB から
rusEFI の verbose broadcast を模擬して受信した記録（`OPN-13` / `IT-01`〜`IT-04` / `IT-15`）。

| 項目 | 値 |
|---|---|
| FW | `lcd21`（実 CAN 版、表示デザイン A）`feat/dial-variant-a` |
| 接続 | Mini CAN の Grove: 黒 GND / 赤 5V -> VBus / 黄 TX -> D+ (GPIO20) / 白 RX -> D− (GPIO19) |
| 給電 | 本体は CH343 の UART Type-C から。Mini CAN は本体の VBus から 5V（端子台に 12V は入れない） |
| 送信側 | PCAN-USB（`PCAN_USBBUS1`）+ `tools/pcan_send.py`、500 kbps、ベース `0x200` |
| 採点 | `tools/bench_check.py` |

## 結果

| 試験 | モード | 結果 | 実測 |
|---|---|---|---|
| `IT-01` / `IT-15` 受信 | `drive` 45 秒 | **PASS** | 120 f/s（6 ID x 20 Hz）、喪失の誤検出 0 行、鮮度 最大 38 ms、tec=0 rec=0、描画 最悪 63 fps |
| `IT-03` 高負荷 | `burst` 20 秒 | **PASS** | 1,197-1,203 f/s、取りこぼし（ovf）0 |
| `IT-02` 途絶 | `dropout` 25 秒 | **PASS** | 送信停止の 2 秒後から喪失（ageL 最小 2,119 ms）、古い値を出さない、再開で復帰 |
| 無効値（`UT-09` の実機確認） | `invalid` 15 秒 | **PASS** | λ=0 / EGT=0 を採用しない（全行喪失）、DLC 不足を破棄して数える |
| 全ゾーン | `sweep` 30 秒 | **PASS** | 5 ゾーンすべて、EGT 305-995 °C、描画 最悪 40 fps |
| EGT 警告・危険（`QT-05` のうち受信側） | `egt-danger` 40 秒 | 受信 PASS / 描画 **FAIL** | 描画 最悪 17 fps（下記） |
| `IT-04` 送信しないこと | `--listen`（観測中にリセット） | データフレーム **0 件** / エラーフレーム **1 件** | 下記（`OPN-18`） |

## 起動直後のエラーフレーム（`OPN-18`）

観測中に本体をリセットすると、毎回 1 件、PCAN がエラーフレーム（ID 4 = スタッフエラー）を報告した。
リセットを 2 秒押し続けてから離す試験で、**押した瞬間には出ず、離した瞬間（起動開始から数 ms 以内）に出る**ことを確認した（2 回とも同じ）。

```
  2.731s  >>> EN low (reset asserted)
  4.732s  >>> EN high (reset released -> boot)
  4.735s  ERROR-FRAME 0x004  dlc=4  01 00 29 00
```

ファームウェアが動き出す前（ROM が USB PHY を扱っている間）に D+（= CAN TX）が一瞬 Low になり、トランシーバがバスを
ドミナントにしていると考えられる。データフレームは送っていない（`SYS-07` は満たす）が、起動時にバスを乱さないという
`IT-04` の趣旨からは外れる。**エラーカウンタが上限に近づかないことから受容とした**（`OPN-18`）。

## EGT 危険中の描画（デザイン A）

危険域でリムを 2 Hz で点滅させると、切り替えのたびに 1 フレーム 17-52 ms（無効領域 最大 4 万 px）かかる。
外周の細い円を 15° ごとに分けても、斜めの区間の外接矩形がそれぞれ 45 px 角ほどになり、24 個で面積がかさむため。
点滅の切り替えは秒 4 回なので、針が動いている状況（`sweep`）では最悪 40 fps を保つ。`egt-danger` は λ が一定で
その秒の描画が点滅のフレームばかりになり、1 フレーム平均で 17 fps と判定された。

## 試験ツールの修正（この試験で見つかったもの）

| 不具合 | 影響 | 修正 |
|---|---|---|
| 送信プロセスの出力を読まずにパイプが詰まり、約 24 秒で送信が止まる | 喪失の誤検出 19 行 | PR #4 の修正を取り込み |
| シリアルを開くと DTR/RTS が有効になり、LCD-2.1 がリセットされる（CH343 の自動書き込み回路） | 起動直後の数秒（360-408 f/s、最初の全面描画 53 ms）が採点に混ざる | DTR/RTS を下げたまま開く |
| 途絶・無効値モードにも通常の鮮度判定を当てる | 正しい動作を FAIL と判定 | モード別の判定（喪失になること・復帰すること・無効値を採用しないこと） |
| 本体のカウンタ（起動からの累積）の絶対値で判定 | 前の試験の DLC 不足を引きずって FAIL | 試験の間の増分で判定 |
| `--listen` がエラーフレームと PCAN の状態通知をデータフレームと区別しない | 起動時のバスの乱れを見落とす / 誤認する | `ERROR-FRAME` と時刻を表示 |

## `IT-17` λ センサの状態表示（`SYS-22`）

`pcan_send.py` の新モードで再現し、本体のシリアルに出る判定（`sensor=`）を 1 秒ごとに記録した。受信は毎秒 160 フレーム
（ECU 120 + WBO 40）で、デュアルフィルタが WBO の `0x190` / `0x191` を通していることも確認した。

| モード | 判定の推移 | 結果 |
|---|---|---|
| `wbo-warmup` | `OFF 25°C`（0-4 秒）-> `WARMUP 34`〜`705°C`（4-16 秒）-> `CHECK 770°C`（16-18 秒）-> `OK`（18 秒〜）。周期の頭で `OFF` にその場で戻る | **PASS** |
| `wbo-fault` | `OFF` -> `WARMUP 127`〜`367°C` -> `FAULT_NO_HEAT 385°C` | **PASS** |
| `ecu-warmup`（WBO のフレームなし） | `OFF` -> `WARMUP`（温度なし）-> `OK` | **PASS** |
| `drive`（デグレ確認） | 120 f/s、喪失の誤検出 0、鮮度 最大 35 ms、描画 最悪 63 fps | **PASS** |

`NO_SIGNAL` は送信が 2 秒以上止まったとき（試験と試験の間）だけ出た。画面の文言・色はカメラ未接続のため未確認
（ユーザーが実機で目視）。
