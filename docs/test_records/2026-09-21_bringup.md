## 1. 解決した未解決事項

| ID | 結論 |
|---|---|
| `OPN-02` | CAN Unit は **PORT.A** に接続。**TX = G13 / RX = G15**。PORT.B (G1/G2) 設定のままでは `rx=0` かつ `rec=0`（RX ピンに信号が来ない状態）になり、切り分けの指標として有効だった |
| `OPN-06` | M5Dial に **PSRAM は非搭載**（ESP32-S3FN8）。`DOC-12 §7.1` |
| `OPN-07` | TWAI は GPIO マトリクス経由で I2C 用ポート (PORT.A) にも割り当て可能 |
| `OPN-08` | **Listen Only は 2 ノード構成のバスでは成立しない**（下記 §2） |

## 2. 発見した設計上の欠陥（`RSK-10`）

Listen Only モードは ACK を返さない。バス上が送信側と本機の 2 ノードだけのとき、
送信側はフレームを完了できず再送を繰り返す。実測した現象:

| 観測項目 | Listen Only | NORMAL（修正後） |
|---|---|---|
| 受信レート（6 フレーム × 20 Hz 送出時） | **3650 f/s**（同一フレームが約 180 回再送） | **120 f/s**（期待値どおり） |
| λ 表示 | `(none)` — 先頭フレーム `0x200` が再送に張り付き、`0x207` がバスに出られない | `1.000` |
| EGT 表示 | `(none)` | `500` |
| PCAN の状態 | `BUS_WARNING` (status=8) | 正常 |

`0x207` のみを単独送出した場合は Listen Only でも `lam=1.000` を受信できたため、
デコーダ自体には問題がなく、**先頭フレームが再送に張り付いて後続がバスに出られない**
ことが原因であると特定した。

NA ロードスターは純正 CAN を持たないため「rusEFI + 本機」の 2 ノード構成になりやすく、
実車では rusEFI 側がバスオフに陥る。`RSK-06`（誤送信）を避けるつもりで入れた Listen Only が、
逆に ECU の CAN を壊すという逆転が起きていた。

**対応**: `DEC-04` を NORMAL モードへ変更（`DOC-11` / `DOC-12` / `DOC-20` / `DOC-22` / `DOC-41` を更新）。
`RSK-06` は「送信 API 非実装 + 送信キュー長 0 + CI の静的検出」の 3 層で担保する。

## 5. 追加で発見・修正した不具合（`SignalStore` の seqlock）

UI のフォント拡大後、`--mode sweep` のログで **受信が 120 f/s で継続しているのに
`lam=(none)` `egt=(none)` が単発で現れる**ことに気づいた。
λ と EGT が同時に落ちるため値の妥当性ではなくスナップショット取得の問題と判断。

原因は `SignalStore::snapshot()` の再試行ループ。書き込み中（seq が奇数）のとき
即座に次の試行へ進んでいたため、**8 回の再試行が書き込み側のクリティカルセクション
1 回の内側に収まり**、一度も読み出せないまま「全信号が未受信 = 全部 Lost」の
スナップショットを返していた。受信が正常でも一瞬 `NO SIGNAL` が出る。

| | 修正前 | 修正後 |
|---|---|---|
| 20 万回の読み出しでの誤 `Lost` 検出数（`UT-15`） | **132,746 回 (66 %)** | **0 回** |
| 実機 30 秒間の `(none)` 出現（sweep 中） | 単発で発生 | **0 件 / 28 ログ行** |

対策は `DOC-21 §5.1`、回帰テストは `UT-15`。
