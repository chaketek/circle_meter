# 最新版に更新する（配布先ユーザー向け）

手順書は `docs/user/07_update.md`。相手は Git をほとんど使ったことがない人。

## 守ること

- **ユーザーの変更を消す操作（`git reset --hard`、`git checkout -- .`、`git clean`、`git stash drop`、`--force` 付きの操作）は、
  何が消えるかを説明して明確な同意を得るまで実行しない。** 迷ったら実行しない。
- `user/` フォルダは git の管理対象外なので、更新で消えも上書きもされない。そう伝えて安心してもらう。
- 専門用語は一言で言い換える（「git pull = 作者の最新版をダウンロードして手元に反映すること」）。

## 手順

### 1. 手元の状態を確かめる（読むだけ）

```powershell
git status --porcelain
git branch --show-current
```

- 何も出ない、かつブランチが `main` → 手順 2 へ。
- `user/` 以外のファイルが変わっている → ユーザーが意図せず作者のファイルを書き換えている。
  変わっているファイルを見せ、「このままだと更新できません。変更を一時的に退避して更新しますか？」と聞く。
  同意があれば `git stash push -m "update-meter で退避"` で退避し、更新後に `git stash list` で残っていることを伝える（勝手に戻したり消したりしない）。
- `main` 以外のブランチ → 理由を聞き、`main` に戻ってよいか確認する。

### 2. 更新前の位置を控える

```powershell
git rev-parse HEAD
```

出てきた 40 文字（コミットの番号）を手順 4 で使う。

### 3. 最新版を取り込む

```powershell
git pull --ff-only
```

- `Already up to date.` → 「すでに最新版です」と伝えて終わる（書き込みは不要）。
- `Not possible to fast-forward` など → 手元に作者の版と食い違う記録がある。強制はせず、出力を見せて作者に相談するよう案内する。
- ネットワークのエラー → 接続を確かめてもう一度。

### 4. 何が変わったかを伝える

```powershell
git log --oneline <手順 2 の番号>..HEAD
git diff <手順 2 の番号>..HEAD -- user/user_config.example.h
```

- コミットの一覧は、ユーザーに関係ありそうなもの（表示・設定・不具合修正）を平易な言葉で 3〜5 行にまとめる。
- 雛形に **新しい `USER_*` 項目**が増えていたら紹介する（ユーザーの `user_config.h` には自動では足さない。
  使いたい場合だけ `customize-meter` の手順で足す）。項目の名前が変わったり無くなったりしていたら、
  ユーザーの `user_config.h` に古い名前が残っていないか確かめ、あれば直し方を提案する。

### 5. 書き込む

`flash-meter` Skill に従って、いま使っている機種（LCD-2.1 / M5Dial）と種類（デモ / 車両用）で書き込み、`meter_log.py` で確かめる。
更新でロゴの置き場所などが変わった場合は、ビルドのログ（`logo:` で始まる行）の案内に従う（例: 古い `user/logo.cpp` が残っていたら `python tools/make_logo.py --user` で作り直す）。
ビルドで止まった場合、作者の更新で設定の範囲が変わった可能性がある。メッセージを日本語でそのまま伝える。
